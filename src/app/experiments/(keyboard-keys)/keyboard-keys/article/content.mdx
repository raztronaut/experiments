# Keyboard Keys

I wanted to build a keyboard shortcut prompt that actually feels like pressing real keys. Not a flat rectangle with a border. Something with depth, with a physical press animation, and with consequences if you get it wrong.

The result is a `⌘ + ⇧ + P` sequence where each key lights up in order, presses down when you hit it, and the whole thing either celebrates with confetti or shakes and roasts you.

## The key component

The core of this is a single `Key` component that renders a 3D-looking keyboard key using pure CSS. No canvas, no SVG, no images.

```tsx
<button className="group relative h-16 w-16 translate-y-0 transition-all duration-75">
  {/* Shadow/depth layer */}
  <span className="absolute inset-0 rounded-xl bg-neutral-800 translate-y-1" />

  {/* Main key surface */}
  <span className="absolute inset-0 flex items-center justify-center rounded-xl border border-neutral-700 bg-gradient-to-b from-neutral-800 to-neutral-900">
    {/* Shine highlight */}
    <span className="absolute inset-x-2 top-1 h-px bg-gradient-to-r from-transparent via-white/20 to-transparent" />

    <span className="text-neutral-300 font-semibold">⌘</span>
  </span>
</button>
```

The depth comes from stacking two rounded rectangles. The bottom one (the shadow) is offset 4px down via `translate-y-1`. The top one (the surface) has a gradient from slightly lighter to slightly darker, plus a thin shine line across the top. When you press it, the surface translates down to meet the shadow.

That's it. No 3D transforms, no perspective. Just two layers and a translate.

## The state machine

Each key in the sequence has a state: `idle`, `active`, `completed`, `error`, or `success`. The sequence tracks which key the user should press next.

```tsx
type KeyState = "idle" | "active" | "completed" | "error" | "success";

const INITIAL_KEYS = [
  { label: "⌘", keyCode: "Meta", state: "active" },
  { label: "⇧", keyCode: "Shift", state: "idle" },
  { label: "P", keyCode: "p", state: "idle" },
];
```

When the user presses the correct key, it transitions from `active` to `completed` and the next key becomes `active`. Each state maps to a different color scheme -- green for completed/success, neutral for idle/active, red for error.

The key insight is that the state machine is dead simple. There's no complex graph. It's just: "what index are we at, and did the user press the right key?" Everything visual comes from mapping those five states to colors.

## The fun part: consequences

The boring version would just flash red and reset. Instead, the error handling escalates.

Every wrong press increments an error counter. After the second error, snarky messages start appearing:

```tsx
const messages = [
  "are you even trying? 🤔",
  "okay this is getting embarrassing...",
  "💀",
  "at this point you're just testing me",
  "im gonna ban you fr",
];
```

After 17 errors (cycling through all five messages three times each), the UI locks you out for 5 minutes with a full-screen overlay and a countdown timer. The lockout state persists across re-renders because it's managed in component state with `setInterval`.

This is what makes it feel alive. The interaction has personality. It remembers how many times you've failed and responds accordingly.

## The confetti

Success triggers a confetti burst from each key individually. Each key spawns 15 particles with deterministic randomness (seeded by key index + particle index, not `Math.random()`), so the animation is consistent across renders.

The particles are plain `div` elements animated with a CSS `@keyframes` that translates them outward from center using CSS custom properties for the end position:

```css
@keyframes confetti-burst {
  0% {
    transform: translate(-50%, -50%) scale(0) rotate(0deg);
    opacity: 0;
  }
  10% {
    transform: translate(-50%, -50%) scale(1.2) rotate(calc(var(--rotation) * 0.1));
    opacity: 1;
  }
  100% {
    transform: translate(calc(-50% + var(--end-x)), calc(-50% + var(--end-y) + 40px))
      scale(0.3) rotate(var(--rotation));
    opacity: 0;
  }
}
```

Each particle gets a unique `--end-x`, `--end-y`, and `--rotation` via inline styles. The `+ 40px` on the Y axis simulates gravity, pulling particles down at the end. No physics engine needed.

## What I'd do differently

The keyboard event handling has some quirks. `e.key` returns different values depending on whether Shift is already held (e.g., `P` vs `p`). The current code handles this with `.toLowerCase()` but a more robust approach would use `e.code` (physical key codes) instead of `e.key` (logical key values).

The confetti could also use `requestAnimationFrame` instead of CSS keyframes for more control -- pausing, reversing, or chaining with other animations. But for a burst-and-fade effect, CSS keyframes are simpler and perform fine.
