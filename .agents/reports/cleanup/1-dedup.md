# Dedup / DRY Report

Source: `jscpd` clone report (`.agents/reports/cleanup/raw/jscpd/jscpd-report.json`) — 118 clones, 2,584 duplicated lines, 6.65% of 38,873 lines. Cross-referenced against the actual files plus targeted grep for tool-missed patterns (reduced-motion hooks, clamp/lerp math, idle-callback helpers, `?debug` detection).

## Critical Assessment

DRY health here is **good, and most of the reported "duplication" is either intentional or low-value**. The 6.65% figure is inflated by three benign categories that should NOT be chased:

1. **Scaffold boilerplate across experiments** (the largest cluster by far). Every `src/app/experiments/(name)/layout.tsx`, `error.tsx`, and `article/page.tsx` is generated by `npm run new:experiment` and is *deliberately* a self-contained copy so each experiment owns its own `<html>`/`<body>` and ships independently. jscpd flags ~70 of the 118 clones here (the `(3d-crt-display)` layout alone pairs with a dozen others; one `error.tsx` body pairs with 21 siblings). Collapsing these into shared imports would fight the architecture, not help it. The right lever for this category is the *scaffold template*, not the generated output — except where a genuinely shared, presentational sub-component already exists or can live in `src/components/ui`.

2. **Cross-experiment algorithm duplication** (game-of-life pair, rabbithole pair). `bugged-out-game-of-life-shader-experiment` and `game-of-life-shader` share ~90 duplicated lines across `LifeSimulation.tsx` and `simulation.worker.ts`; `rabbithole-chat-gallery-explore/VisualiserLogic.ts` and `rabbithole-chat-preloader/Gallery.ts` share gallery math. These are the textbook "by-design duplication" the architecture protects. **Flag, do not touch** — any fix would require a forbidden cross-experiment import.

3. **Genuinely-fixable duplication**, which is a small but real slice. The highest-value wins are: (a) a shared route-`error.tsx` body (the inline `ExperimentErrorBoundary` already exists but solves a *different* problem), (b) a verbatim `runWhenIdle` helper copied between two shared-UI files, (c) a reduced-motion hook reimplemented in ~3 places when a generic `useMediaQuery` already lives in `src/hooks`, and (d) several **within-a-single-file / within-a-single-experiment** clones that are unambiguously safe to extract locally.

Where DRY would *increase* complexity: the per-experiment layouts/articles (parameterizing them couples isolated experiments to a shared abstraction that must then handle every experiment's font/theme/metadata variance), and anything spanning two experiment folders. Where DRY *reduces* complexity: hoisting stable, generic infrastructure (idle scheduling, media-query/reduced-motion, route-error chrome) into the already-established `src/lib` / `src/hooks` / `src/components/ui` shared layer, and de-duplicating logic that repeats inside one file.

Bottom line: ignore ~80% of the jscpd hits as intentional, and pursue the ~6 concrete items below.

## Recommendations

1. **Confidence: High** — Extract a shared route-error component for the ~21 identical `error.tsx` route files.
   - Representative duplicates: `src/app/experiments/(3d-crt-display)/3d-crt-display/error.tsx:1-38` is byte-identical to `src/app/experiments/(404-not-found)/404-not-found/error.tsx:1-38` except the `slug` literal; jscpd pairs this body across 21 experiments, and the header (`src/app/(main)/error.tsx:1-16`) is shared too.
   - Change: add `ExperimentRouteError` to `src/components/ui` (e.g. `src/components/ui/ExperimentRouteError.tsx`) accepting `{ error, reset, slug }`, encapsulating the `useEffect` + `captureExperimentError({ route: "experiment", slug })` + the fallback JSX. Each route `error.tsx` becomes a 6-line `"use client"` wrapper: `export default function Error(props) { return <ExperimentRouteError {...props} slug="3d-crt-display" />; }`. Also update the scaffold template that emits `error.tsx` so new experiments inherit it.
   - Note: this is NOT the existing `src/components/ui/ExperimentErrorBoundary.tsx` — that is a `Component` class boundary for *inline component trees* (no `reset`/`digest`, different fallback). Keep both. No WebGL/animation risk. Touches shared UI → per AGENTS.md "ask first" before modifying `src/components/ui`.

2. **Confidence: High** — Hoist the verbatim `runWhenIdle` helper out of two shared-UI files.
   - Duplicates: `src/components/ui/DeferredAIWidget.tsx:8-21` and `src/components/ui/LocationStatusEnhancer.tsx:8-18` define the same `requestIdleCallback`-with-`setTimeout`-fallback function (jscpd clone `DeferredAIWidget.tsx:6-27 <=> LocationStatusEnhancer.tsx:6-20`).
   - Change: move `runWhenIdle` into `src/lib/utils.ts` (or a small `src/lib/idle.ts`) and import it in both. Pure, generic infrastructure; no visual risk. Both call sites already live in shared `src/components/ui`, so no isolation concern.

3. **Confidence: Medium** — Reuse the existing generic media-query hook for reduced-motion instead of re-implementing it.
   - Duplicates (tool partially missed; found via grep): `src/components/experiments/3d-crt-display/hooks.ts:3-15` (`usePrefersReducedMotion`) and the same `window.matchMedia("(prefers-reduced-motion: reduce)")` + listener pattern in `src/components/ui/wave-background.tsx:275` and `src/components/experiments/luma-morphing/LumaMorphing.tsx:34`. A generic `src/hooks/useMediaQuery.ts:5-22` already exists and is SSR-safe.
   - Change: add a one-line `src/hooks/usePrefersReducedMotion.ts` that calls `useMediaQuery("(prefers-reduced-motion: reduce)")`, and have the shared `wave-background.tsx` use it. For the *experiment* copies (`3d-crt-display`, `luma-morphing`), this is borderline: importing a shared hook is allowed (it's `src/hooks`, not another experiment), but each experiment intentionally carries its own tiny hook for portability. Recommend hoisting only the shared-UI usage with High confidence; leave the in-experiment copies as an optional, owner's-discretion cleanup. Touches animation gating logic → low-risk but verify reduced-motion still triggers visually. Note: `velocity-responsive-design` and `Slideshow.tsx` already use `motion/react`'s `useReducedMotion` — do not disturb.

4. **Confidence: Medium** — De-duplicate the repeated key-advancement logic *within* `KeyboardKeys.tsx`.
   - Duplicate: `src/components/experiments/keyboard-keys/KeyboardKeys.tsx:98-150` (`handleKeyDown` correct/wrong-key branch) is ~53 lines near-identical to `KeyboardKeys.tsx:198-250` (`handleKeyClick`). Largest single-file clone in the report.

Stays entirely within one experiment — fully safe. Pure interaction/state logic; no shader risk, but it drives `setIsShaking`/timeout animation state so confirm the shake + lockout timing is unchanged after extraction.

The two `article/components.tsx` cases live inside one experiment's article folder → safe (no cross-experiment boundary crossed). No WebGL/animation risk. Each is small; do opportunistically.

6. **Confidence: Low** — Two shared dev/UI components share boilerplate; minor, optional.
   - `src/components/dev/DevToolsInjector.tsx:44-54` and `src/components/dev/R3FDevToolsInjector.tsx:28-38` share the `useState(false)` + `useEffect` reading `?debug` from `URLSearchParams`; a `src/hooks/useDebug.ts:11-14` hook already exists (uses `useSearchParams`). `src/components/mdx/controls/Checkbox.tsx:32-47 <=> Switch.tsx:32-47`, and `src/components/ui/experiments/InteractivePreviewMedia.tsx:113-127 <=> StaticExperimentMedia.tsx:118-132` also share small blocks.

The Checkbox/Switch and media-component overlaps are small and the components are intentionally distinct shadcn-style primitives; extracting risks coupling two UI primitives for marginal gain. Low value — list for completeness, recommend skipping unless touching these files anyway.
