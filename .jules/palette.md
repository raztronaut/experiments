## 2025-03-20 - Explicit button types in Error Boundaries
**Learning:** React Error Boundaries (like `ExperimentErrorBoundary`) can unexpectedly submit forms if their fallback UI includes `<button>` elements without explicit types (which default to `type="submit"` in HTML), leading to jarring page reloads or side effects when an error occurs inside a form context.
**Action:** Always add `type="button"` to `<button>` elements in fallback UIs and generic components unless they are explicitly intended to submit a form.
## 2024-04-16 - Accessible Toggle Buttons and Icon Buttons
**Learning:** In custom toggle buttons (like those in `ExpandedControls`), using `aria-pressed={isActive}` accurately conveys the toggle state to screen readers. For icon-only buttons (like in `SendButton`), using `aria-label` provides a descriptive name. Furthermore, ensuring interactive elements do not have `tabIndex={-1}` allows for natural keyboard navigation, and applying consistent `focus-visible:outline-hidden focus-visible:ring-1 focus-visible:ring-ring` classes creates a clear, accessible focus ring.
**Action:** When implementing or modifying custom toggle buttons, use `aria-pressed` to indicate state. For all interactive elements, ensure proper `aria-label`s are applied, avoid using `tabIndex={-1}` unless specifically hiding from tab order, and apply the project's standard `focus-visible` classes.
