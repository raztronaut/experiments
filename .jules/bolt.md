## 2025-04-04 - Reading Time Estimation using String Pattern Matching over Array Separation
**Learning:** Using an external library (like `reading-time-estimator`) or `String.prototype.split()` to estimate reading time allocates large arrays in memory when run on massive MDX content. This produces extremely high garbage collection overhead and execution latency when processing hundreds of articles in succession (like feed or static site generation), taking hundreds of milliseconds vs sub-10ms.
**Action:** For reading time estimations on large strings, always prioritize regex pattern counting (`text.match(/\S+/g)?.length`) over splitting strings into word arrays or using heavy NPM dependencies. It achieves the exact same 200WPM metric entirely within the regex engine without creating excessive memory garbage.
